https://www.ov-berlin.de/ · 2026-11-08T19:20:31.090Z · mobile, tablet, desktop

Summary

What visitors are trying to do

  • Find films with English audio: reached on mobile in 4 actions, reached on desktop in 1 actions
  • Open a film and find where to get tickets: reached on mobile in 1 actions, reached on desktop in 1 actions
  • Open a cinema's page to see what it shows: reached on mobile in 1 actions, reached on desktop in 2 actions

Where the design makes it harder

  • Focused controls are covered by another element: View details for Staatsschutz, Add to watchlist, View details for Queens of the Dead, Add to watchlis
  • Opening "Open navigation menu (narrow window)" leaves focus outside the panel.
  • "English audio" changes appearance when active, but its state is not exposed to assistive technology.
  • Most text on this page is 12px, below the 14px limit.
  • 3 button(s) have no fill, border, underline or icon, for example "More about this movie".

What should change first

  • Keep focused controls clear of sticky bars.
  • Move focus into the panel when it opens.
  • Expose the state with aria-pressed or an equivalent.
  • Bring body size and line length within limits.
  • Give these buttons a visible boundary or marker.

How we will know it worked

  • No focused control is hidden by a sticky element
  • Focus is inside the panel after it opens
  • The control exposes its current state in the accessibility tree
  • Body text is at least 14px
  • Each button has a fill, border, underline or icon

Each issue states its own validation method. The agent re-measures on every run.

Tonight/Tomorrow/Weekend chips repeat the date controls. "English audio" is a quick chip, while Language is a separate dropdown. A visitor may not know whether these controls combine or overwrite each other.

Recommendation

Group the controls under two labelled headings, "When" and "Language & subtitles". Show "English audio" as the selected state of the Language filter.

Evidence, cause, implementation and validation

Usability principle

Information architecture

Observed evidence

The tablet and desktop pages show the date strip, then the quick chips (Tonight, Tomorrow, Weekend, English audio), then the Language dropdown. On mobile all of this is behind "Filters". On the page: "English audio".

Reproduction

  1. Open / on desktop
  2. Compare the date strip, the quick chips and the dropdown filters

Likely cause (hypothesis)

Shortcuts were added next to the full filters without being grouped.

Cross-check

weak: S24 shows the chip row above the Language dropdown, and S07 shows the mobile filters collapsed. Whether users are confused about how the controls combine is an assumption. S25 shows the chip and dropdown staying in sync.

Alternative

Drop the duplicate Tonight/Tomorrow/Weekend chips.

Expected benefit

Each filter has one place and a clear state.

Implementation guidance

Link each chip's active state to its dropdown value.

Acceptance criteria

  • Each filter is available in only one control group
  • Selecting a chip updates the matching dropdown label

How to validate

Run a task test on switching date and language on a phone.
